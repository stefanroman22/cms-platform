## GitHub setup

- 2026-04-29: GitHub MCP at api.githubcopilot.com (claude.ai web connector) is NOT auto-registered in Claude Code CLI sessions. Don't assume MCP availability — fall back to `gh` CLI (verify active account matches the intended owner) or REST via `agents/.../github.py`. Surface MCP unavailability immediately and suggest the fallback. Triggered by: agent halted Phase 1 because spec required MCP and only `gh` CLI was available.
- 2026-04-29: Verify `gh` CLI active account matches the intended repo owner before creating repos (`gh api user --jq .login`). User may have multiple accounts in keyring. Triggered by: gh was authed as a different user than the project owner.
- 2026-06-08: Strip GitHub branch protection on the production branch during provisioning (`github.ensure_branch_unprotected`, called in `_vercel_setup` right after the Vercel protection disable). A protected, PR-only prod branch is incompatible with the S1.5 fast-forward promotion — it can only advance via PR-merge commits, which permanently diverge it from `cms-preview` and wedge every deploy ("cannot fast-forward ... diverged"). The Slack ✅ approval is the real production gate. Triggered by: it-global-services `main` was manually branch-protected; every production merge failed 422 "Update is not a fast forward".
- 2026-06-17: GitHub repo names are CASE-INSENSITIVE for uniqueness — creating `akris` collided with the client's existing `Akris` repo ("Name already exists"). Use a distinct name (e.g. `<slug>-website`) rather than force-clobbering the client's original repo. Also reconfirmed [[feedback_git_credentials]]: `gh` createRepository can act as the WRONG keyring account (jimmedeknatel8) even when `gh api user` shows stefanroman22 — `gh auth switch -u stefanroman22 && gh auth setup-git` fixes it. Triggered by: Akris frontend repo creation.

## Phase 2 — Scan rules

- 2026-04-29: When a site has Why-Choose-Us (or pillars / value-props / differentiators) repeating cards on multiple pages with overlapping themes, default to a SINGLE shared `key_features` repeater referenced by all pages (place under "General"). Pages render all items or a slice. Triggered by: it-global-services had 6 home reasons + 4 about pillars with conceptual overlap; user merged into one shared repeater.
- 2026-06-06: The language-SWITCHER control/labels (chrome) stay excluded; DETECT the locale set from `i18n/routing.ts` + `messages/<locale>.json` and import per-locale CONTENT as first-class CMS data. Supersedes the 2026-04-29 rule about language toggles being configuration-only. Triggered by: multilingual sites (e.g. Next.js + next-intl) have real per-locale content that must be seeded into the CMS.
- 2026-06-17: CMS→CMS migration (the source ALREADY has a headless CMS, e.g. Sanity): export content via the source's public read API (Sanity GROQ over HTTP — no MCP needed), then map source document types → the 8 CMS service types: singletons → `key_value`/`text_block`; rich text (Portable Text) → `text_block`/`richtext` **Markdown** (convert blocks/marks/links; single `\n` → markdown hard break + render with `remark-breaks`); nested arrays (tables-of-rows, categories-of-refs) → FLAT `repeater`s carrying a grouping field (e.g. `table_heading`/`category`) the site re-groups on render; per-item images → repeater `url` fields (repeaters have NO per-item upload). Fetch via a UTF-8-aware client (a curl→console pipe mangles €/curly-quotes; the data is fine). Triggered by: Akris was a Vite+React site on Sanity.

## Phase 4 — Integration rules

- 2026-06-11: Booking STAFF have an optional avatar (`booking_resources.image_url`). The connector seeds it from `booking.resources[].image_url` (match a staff portrait from a team/about section or the `team_members` repeater by name); when empty, the owner calendar and the customer booking flow render a default placeholder avatar (a photo is never required). The generated `lib/booking.ts` `Resource` type now includes `image_url?`. Avatars are editable later in the dashboard under **Bookings → Staff**. Triggered by: Fresha-style day calendar + customer booking flow needed per-staff photos.
- 2026-06-11: REPEATER `_schema` MUST be folded into the seed content. The seed `PUT /services/<key>?seed=true` full-replaces a service's content, so an items-only `initial_content` blob clobbers the `_schema` (per-item field defs) that the create `POST` seeded — leaving the dashboard with an uneditable "This repeater has no field schema defined" card AND silently disabling repeater translation (the translator keys off `_schema`). `_schema` is part of the repeater content shape `{_schema, items}`, so carry it on every seed (default + each `?locale=`). `scan.py:_repeater_seed_content` now grafts `item_schema` onto repeater seed content; backend `save_service` also re-grafts a missing `_schema` defensively. Triggered by: ALL 6 of samir-kapsalon's repeaters shipped uneditable (items present, `_schema` null in both draft+published, both locales).
- 2026-04-29: STANDING RULE — every site this agent integrates uses Resend for email delivery (via the CMS backend's `/forms/<slug>/<form_key>` endpoint + `RESEND_FROM_EMAIL`). Always migrate sites away from third-party email clients (EmailJS, Formspree, custom SMTP) during Phase 4. Drop their imports + `NEXT_PUBLIC_*` env vars. Triggered by: it-global-services used EmailJS; user confirmed Resend is the default for all future sites.
- 2026-06-06: Provisioning order for multilingual sites: (a) seed DEFAULT locale via `PUT /projects/<slug>/services/<key>` (no `?locale=` param); (b) import each non-default locale via `PUT …?locale=<l>`; (c) set `{default_locale, locales}` LAST via `PATCH /admin/projects/<slug>`. Setting locales last prevents the backend's auto-translate from overwriting human translations imported in step (b). Triggered by: auto-translate clobbered per-locale seeds when PATCH ran before PUT imports.
- 2026-06-06: The CMS endpoint env var set in Vercel must be the locale-less base `{cms_endpoint_base}/content/{slug}`. The site's `i18n/request.ts` appends `/{locale}` at runtime. Framework-aware prefix: `NEXT_PUBLIC_CMS_ENDPOINT` for Next.js, `VITE_CMS_ENDPOINT` for Vite. Triggered by: multilingual Next.js sites needed NEXT_PUBLIC_* and locale-less base to fetch per-locale content correctly.
- 2026-04-29: Forms endpoint path is `/forms/<slug>/<form_key>` — NOT `/api/forms/submit`. Phase 4 spec doc had wrong path; it has been corrected. Triggered by: AGENTS.md said `/api/forms/submit`.
- 2026-04-29: Backend has NO public POST `/projects` endpoint to create a CMS project row. Either insert directly via Supabase Management API (PAT) or have the user click "Create New Project" in the CMS admin UI. Document this in Phase 4 sub-step 0. Triggered by: agent assumed POST `/projects` existed.
- 2026-04-29: Set the project's `allowed_origins` array (postgres `text[]`) AFTER deploys land — must include both `production_url` and the preview branch alias. The admin PATCH endpoint does not whitelist this column; update via Supabase SQL. Triggered by: PATCH returned `{"updated":3}` (skipped allowed_origins).
- 2026-04-30: `AdminProjectPatchIn` (backend Pydantic schema) silently discards unknown fields. Pre-fix, `website_url` was NOT in the model so PATCHing it was a no-op (and `{"updated":N}` reflected only the accepted fields, hiding the silent drop). Post-fix the schema now includes `website_url` so the admin endpoint accepts it. Phase 4 must always set `website_url` (in addition to `production_url`) so the project page's "Live website" card and the admin settings form both populate. Triggered by: client-side card stayed hidden because `/projects/<slug>/settings.website_url` came back null even though Phase 4 thought it had been set.
- 2026-04-29: For Next.js client sites, env-var keys are `NEXT_PUBLIC_CMS_ENDPOINT` and `NEXT_PUBLIC_CMS_PREVIEW_TOKEN` (NOT the Vite `VITE_*` variants the existing `scan.py` hard-codes). Detect framework from `next.config.*` and select the right prefix. Triggered by: it-global-services is Next.js; agent set the right vars manually.
- 2026-04-29: Backend `/content/<slug>/draft` expects header `X-CMS-Preview-Token`, NOT `Authorization: Bearer`. The CMS fetcher in the client repo must use that exact header. Triggered by: Vercel preview build failed with 401 because client used `Authorization: Bearer`.
- 2026-04-29: Static export (`output: "export"` in next.config) DISABLES ISR (`fetch(..., {next:{revalidate:60}})`) so admin CMS edits never surface on the deployed site without a rebuild. Default for CMS-driven Next.js sites: omit `output:"export"` and let Vercel run SSR + ISR. Triggered by: it-global-services had `output:"export"`; we removed it so publish reflects within 60s.
- 2026-04-29: Vercel default project setting `ssoProtection: 'all_except_custom_domains'` makes preview-branch aliases gated behind Vercel auth. The default `<project>.vercel.app` production URL is treated as a custom domain and is public. Document this so Phase 5 expects 401 on the preview alias unless a custom domain is added or sso is disabled.
- 2026-04-29: Newly created services need an explicit publish call (`POST /projects/<slug>/publish`) before the public `/content/<slug>` endpoint reflects seeded values. Without publish, production fetch returns empty service shells. Triggered by: production page rendered no content until we ran the publish call.
- 2026-06-13: PREVIEW-TOKEN / DRAFT-PREVIEW chain was broken end-to-end (cms-preview + localhost showed PUBLISHED, never SAVED drafts). Three compounding bugs, all now fixed in scan.py + phases/4-integration.md §4.5 + §4.1.6 + the new 5i: (1) scan.py PATCHed `preview_token` onto the project row, but AdminProjectPatchIn DELIBERATELY drops it (audit BE-004 token-fixation) → DB token stayed NULL → /draft 401s for everyone → drafts never visible. (2) scan.py set the Vercel token under `{prefix}CMS_PREVIEW_TOKEN` (NEXT_PUBLIC_…, a client-bundle credential leak) while the backend rotate endpoint sets the server-only `CMS_PREVIEW_TOKEN` — mismatched keys, so rotate could never repair a live site. (3) generated `lib/cms-content.ts` had NO draft branch (stripped `/draft`, always fetched published). FIX: token is now provisioned via `POST /admin/projects/{slug}/rotate-preview-token` (the single writer of BOTH DB + Vercel), set-if-absent (idempotent, never rotate when a token exists); the connector mirrors the returned token onto Vercel under the server-only key `CMS_PREVIEW_TOKEN`; the `{prefix}CMS_ENDPOINT` is the locale-less base on BOTH targets (no `/draft` suffix) and the generated cms-content.ts appends `/{locale}` + `/draft` and the `X-CMS-Preview-Token` header + `no-store` when the token is present (draft on preview/localhost), else published+ISR, with a never-throw fallback. Vercel "duplicate" env vars = the NORMAL per-environment (Preview vs Production) split, NOT a bug; a real duplicate only appears if a re-run requests a different target SET than the stored row. Triggered by: Stefan reported samir cms-preview/localhost never showing saved edits + apparent duplicate Vercel env vars. Connector tests updated (test_scan_vercel_phase.py); 82 connector tests green.
- 2026-06-14: §5i audit of 3 shipped sites surfaced TWO new partial-wiring classes beyond the original "service totally unwired" bug — now mandated in phases/4-integration.md §4.1.6.3/4.1.6.4 + 5i. (1) MULTI-RENDER-PATH partial wiring: the same data is rendered in several places but only SOME read the CMS. it-global-services hardcoded the logo in Header (every page)/Footer/MobileMenu while only Home/About used CMS general_logo; samir-kapsalon read staff name/portrait/tags from the static TEAM constant on the team page while only role/bio came from the CMS team_members repeater; laurian renders cv/experience/projects/hobbies from static constants in the Terminal emulator while the GUI views are CMS-wired. RULE: a service is "wired" only if EVERY surface that displays it (chrome, every page, alternate views) reads the resolved CMS value; a static constant may live ONLY as a fallback inside resolveSite, never as a parallel render path — grep ALL usages, not just the primary. (2) ORPHAN DB SERVICE: laurian had a stray empty `contact_intro` text_block in project_services that was absent from the repo config + referenced nowhere (colliding display_order) → editable-but-inert dashboard clutter. RULE: after provisioning, diff project_services against the manifest; deprovision (or wire) any service the repo can't render. Fixes shipped: samir team_members wiring + it-global logo threading (committed to each cms-preview, draft-round-trip verified); laurian contact_intro deprovisioned from the DB (its Terminal wiring deferred — the repo had unrelated uncommitted WIP on those files). Also confirmed: client LOCAL repos are often several commits BEHIND their deployed origin — re-base fixes on origin/cms-preview before editing, don't trust the local working copy's staleness.
- 2026-06-13: RESOLVED the samir-kapsalon "content-wiring gap" follow-up (was: services editable in CMS but not driving the live site). Root cause: the generated `lib/cms-content.ts` only deep-merged text whose service key matched a `t()` namespace, so `image`/`gallery` services + `opening_hours`/`contact_info`/`general_brand_name` were dropped (site rendered them from static `lib/site.ts` constants → editing them did nothing, ever). For samir, 9/28 services were inert. Fix pattern (now mandated in [phases/4-integration.md → 4.1.6](./phases/4-integration.md)): `lib/cms-content.ts` injects a `site` namespace covering ALL service types; new `lib/cms-site.ts` `resolveSite(messages)` returns CMS values with fallback to the `lib/site.ts` constants (+ derive tel/IG-URL/address-split, override only hours TIMES); components read via `resolveSite(getMessages()/useMessages())`. ALWAYS audit that every provisioned service has a consumer before declaring Phase 4 done. Triggered by: Stefan reported samir CMS edits (opening hours, contact, gallery uploads) never appeared. Also: edits sit in `draft_content` until **Publish Changes** — the site reads PUBLISHED, so unpublished edits never show even when wired.

- 2026-06-14: The seo_* tables (seo_page_meta/seo_articles/etc.) are the SEO/GEO Optimizer agent's area. NEVER provision them as content services or clobber them. Generated sites only CONSUME the public read endpoints GET /projects/<slug>/seo/public/{meta,articles} (ISR + never-throw fallback); generateMetadata prefers stored seo_page_meta over build-time seo-pro output. Triggered by: SEO/GEO Optimizer Plan 4 cross-agent contract.

- 2026-06-17: The image UPLOAD endpoint (`POST /projects/{slug}/services/{key}/upload`, multipart) is SESSION-auth only (`require_user`) — the admin BEARER key does NOT work (401). To re-host images into Supabase storage: create the client account FIRST, create the project OWNED BY THE CLIENT, log in as the client (capture the `sid` cookie via a cookie jar), then upload (returns a public `cms-files` URL). Gallery content shape is `{items:[url,...]}`. Triggered by: Akris team-photo re-host.
- 2026-06-17: `PUT /services/{key}?seed=true` requires an ADMIN user, i.e. the BEARER path — which BE-011 rate-limits to 10 attempts/min/IP. A burst of create+seed calls hits 429 ("Too many admin auth attempts"). AVOID by doing the content phase entirely on the CLIENT SESSION cookie (NOT rate-limited): login as client → `PUT /services/{key}` WITHOUT `?seed=true` (normal draft save) for each service → `POST /projects/{slug}/publish` (publish is `require_user`/session-only too — bearer 401s it). Send the repeater `_schema` inside content anyway (backend re-grafts defensively). Triggered by: Akris seeding 429'd after the 10 create calls used the bearer budget.
- 2026-06-17: Vite SPA clients fetch published content CLIENT-SIDE at runtime (`GET {base}/content/{slug}`, CORS `*`, no-cache+ETag) — CMS edits appear on the next page load with NO redeploy/ISR. Set `VITE_CMS_ENDPOINT` to the full URL incl. slug; pass `framework='vite'` to Vercel; use `react-markdown`+`remark-breaks` (NOT Portable Text) for text_block/richtext bodies. Build-time `VITE_*` + `loadEnv` `define` vars must be set as Vercel project env (committed `.env*` are gitignored). Triggered by: Akris (Vite+React Router SPA).
- 2026-06-17: A Playwright/headless-browser scraper can usually be replaced by hitting the target SITE'S underlying JSON/RPC API with plain `requests` → fits Vercel Python serverless (no Chromium, no function-size/timeout blowup). Deploy as its OWN Vercel project + GitHub repo; edge-cache the response (`Cache-Control: s-maxage=900, stale-while-revalidate`); point the client's `VITE_API_URL` at it; deploy the scraper BEFORE the frontend so its real prod URL can be baked into the Vite build. Triggered by: Akris ttapp.nl competition scraper (Django+Playwright → Vercel Python).
- 2026-06-18: Vite/SPA clients need the SAME draft-preview chain Next.js sites get — DO NOT skip it (the dashboard "See Preview" button is DISABLED until the project row has a `preview_url`, and a tokenless SPA only ever fetches published). Wire it the SPA way: (1) make the client's CMS fetcher draft-aware — when `VITE_CMS_PREVIEW_TOKEN` is set it fetches `{VITE_CMS_ENDPOINT}/draft` with header `X-CMS-Preview-Token` + `cache:'no-store'` + React-Query `staleTime:0`, falling back to published on any error (never throw); production has no token → published. (2) Create the `cms-preview` branch = production branch (main). (3) Provision the token via `POST /admin/projects/{slug}/rotate-preview-token` (set-if-absent — sets the DB `preview_token` the `/draft` endpoint checks). (4) Set `VITE_CMS_PREVIEW_TOKEN` on the Vercel **preview target ONLY** (client-bundle value, but it only grants draft READ on the non-prod deploy — acceptable for an SPA; never on production). (5) Set `VITE_CMS_ENDPOINT` + the external-API var (`VITE_API_URL` scraper) on BOTH production+preview targets so the CMS AND the scraper run on the preview deploy too (verify the external API sends `Access-Control-Allow-Origin:*`). (6) Deploy main + cms-preview. (7) PATCH the project row `preview_url` = the cms-preview branch alias so the dashboard "See Preview" enables. Triggered by: Akris (Vite SPA) shipped without a cms-preview deploy → "See Preview" was dead + the SPA fetched only published.

## Vite + React 19 (SSG) — framework-aware connector (2026-06-21)

- 2026-06-21: The website-builder now ships Vite + React 19 (SSG) sites alongside legacy Next.js sites; the connector wires them framework-aware with a SEPARATE vite-react branch beside every Next branch (never replacing it). Key differences from Next: env vars are `VITE_CMS_ENDPOINT`, `VITE_CMS_PREVIEW_TOKEN`, `VITE_BOOKING_API_BASE` (no `NEXT_PUBLIC_*`); content lives in `src/lib/cms-content.ts` (client TanStack Query fetch + localStorage persist; `staleTime` minutes for published, `staleTime:0` + `cache:'no-store'` for draft) merged over `src/i18n/messages/<locale>.json` — build-time SSG bakes a published snapshot, client refetch keeps humans fresh (NO ISR, NO `next:{revalidate}`); the react-i18next `t("<service_key>.<field>")` / `messages/<locale>.json` shape is IDENTICAL to next-intl so the deep-merge content logic carries with only path changes (`src/i18n/messages/` not `messages/`, `i18n.language` not the next-intl context); `src/lib/seo-meta.ts` (build-time fetch + optional client TanStack refetch, never throws) + `src/lib/head.ts` (React 19 hoisted `<title>/<meta>/<link>` + coded canonical/hreflang/og:locale/JSON-LD per locale) replace `generateMetadata` entirely; `/blog` + `/blog/:slug` are pre-rendered from build-time article slugs (`GET …/seo/public/articles?locale=`) + client refetch for freshness. Draft branch: `VITE_CMS_PREVIEW_TOKEN` present (preview/localhost `.env.local`) → `{base}/{locale}/draft` with `X-CMS-Preview-Token` header; absent → published. Legacy Next sites keep ISR + `generateMetadata`; the Next-only entries above are superseded for NEW builds. Triggered by: website-builder Plan B — Vite + React 19 SSG as the new default pipeline target (2026-06-21).

## Phase 5 — Testing rules

- 2026-06-06: Draft endpoints require header `X-CMS-Preview-Token: <preview_token>`, NOT `Authorization: Bearer <preview_token>`. Applies to both `/content/<slug>/draft` and `/content/<slug>/<locale>/draft`. Triggered by: preview builds returned 401 when client sent `Authorization: Bearer`.
- 2026-06-18: CONFIRMED-GOOD / STANDING: the Phase 5 acceptance gate is the full 5i round-trip and the agent MUST NOT stop until it passes green: edit a small marker in EVERY section (draft) → assert cms-preview shows ALL markers AND production still shows originals → publish → assert production shows all markers (every section) → revert every section → assert cms-preview reverted → publish → assert production restored byte-identical. Verify in a REAL browser (SPA = client-rendered; check the page that renders each service). HARD-RELOAD NOTE (mention to the client): the SPA caches content in memory (React Query) and the browser HTTP-caches, so after a CMS edit a normal reload usually suffices (preview = no-store + staleTime 0) but a HARD reload (Ctrl/Cmd+Shift+R) guarantees the freshest draft. Persist any scratch/baseline JSON as UTF-8 explicitly — Windows `open(path,'w')` defaults to cp1252 and corrupts €/curly-quotes, breaking a later utf-8 read. Triggered by: Stefan's Akris preview + round-trip request; all 6 services verified preview→publish→revert→publish clean, 0 console errors.
